# Decisões Arquiteturais — Capital Gains Simulator

## ADR-006 — Interface gráfica com formulário e tabelas

**Status:** Aceita

### Contexto

O desafio original propõe uma aplicação de terminal com entrada e saída JSON. O projeto adotará uma interface gráfica desktop, utilizando Java Swing.

### Decisão

A aplicação terá uma janela principal composta por:

- Formulário para cadastro de operações.
- Tabela de operações cadastradas.
- Tabela com os resultados da simulação.
- Painel de resumo financeiro.

O formulário permitirá selecionar o tipo de operação (`BUY` ou `SELL`), informar o preço unitário e a quantidade.

As operações serão processadas somente quando o usuário solicitar a simulação.

### Justificativa

A interface gráfica proporciona uma experiência mais acessível e permite visualizar as operações e seus resultados sem depender de comandos no terminal.

A lógica de negócio permanecerá independente da interface, permitindo implementar futuramente outras formas de interação.

## ADR-007 — Edição e remoção de operações

**Status:** Aceita

### Decisão

A interface permitirá:

- Adicionar operações.
- Remover uma operação selecionada.
- Limpar todas as operações cadastradas.
- Iniciar uma nova simulação.

Não haverá edição direta de operações cadastradas. Para corrigir uma operação, o usuário deverá removê-la e adicioná-la novamente.

### Justificativa

Essa abordagem reduz a complexidade da interface e evita inconsistências entre as operações cadastradas e os resultados anteriormente calculados.

Como a simulação é executada sobre a sequência completa de operações, qualquer alteração na sequência exigirá um novo cálculo.

## ADR-008 — Apresentação dos resultados financeiros

**Status:** Aceita

### Decisão

Os resultados serão apresentados em uma tabela contendo:

| Campo | Descrição |
|---|---|
| Número | Posição da operação |
| Tipo | Compra ou venda |
| Preço unitário | Preço informado |
| Quantidade | Quantidade negociada |
| Valor bruto | Preço unitário multiplicado pela quantidade |
| Resultado | Lucro, prejuízo ou ausência de resultado |
| Imposto | Imposto devido na operação |

Um painel separado apresentará o resumo financeiro da simulação:

- Quantidade final em carteira.
- Preço médio final.
- Prejuízo acumulado.
- Imposto total.

### Justificativa

A separação entre resultados individuais e resumo financeiro facilita a compreensão do comportamento tributário de cada operação e do estado final da carteira.

## ADR-009 — Estado em memória e ausência de persistência

**Status:** Aceita

### Decisão

As operações e os resultados permanecerão em memória durante a execução da aplicação.

Não será utilizado banco de dados, armazenamento externo ou mecanismo de persistência.

Cada nova simulação começará com um estado financeiro independente.

### Justificativa

O desafio não exige persistência. Adicionar banco de dados aumentaria a complexidade sem contribuir para os objetivos centrais da aplicação.

---

## ADR-010 — Independência da interface gráfica

**Status:** Aceita

### Decisão

As regras de negócio não terão dependência de classes ou componentes Swing.

A camada de serviço receberá objetos de domínio e retornará resultados independentes da interface gráfica.

### Justificativa

Essa separação permite testar as regras de negócio sem inicializar componentes gráficos e facilita a evolução da aplicação.

Também possibilita implementar futuramente uma interface CLI ou outra camada de apresentação sem reescrever o cálculo tributário.
